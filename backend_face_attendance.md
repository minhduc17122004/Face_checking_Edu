# Backend Implementation Guide

## AI Face Recognition Attendance System

## 1. Project Overview

This document describes how to implement the backend for the
**AI-powered Face Recognition Attendance System** used in the Vedura
mobile application.

The system uses an **on-device face recognition architecture** where the
mobile device performs face detection and embedding generation. The
backend is responsible for:

-   User authentication
-   Employee/student management
-   Face data synchronization
-   Attendance record storage
-   Device synchronization

Advantages of this architecture:

-   Reduced server load
-   Better privacy for biometric data
-   Offline attendance capability
-   Faster face recognition performance

# 3. Database Design

## 3.1 Users Table

Stores authentication information for teachers/admin.

    users

  Field           Type       Description
  --------------- ---------- -----------------------
  id              int        Primary key
  username        string     Login username
  password_hash   string     Hashed password
  role            string     teacher / admin
  created_at      datetime   Account creation time

------------------------------------------------------------------------

## 3.2 Employees Table

Stores student or employee information.

    employees

  Field          Type       Description
  -------------- ---------- ----------------------
  id             int        Primary key
  name           string     Full name
  student_code   string     Student ID
  class          string     Class name
  avatar         string     Avatar image
  created_at     datetime   Record creation time

------------------------------------------------------------------------

## 3.3 Face Embeddings Table

Stores the face feature vector generated by the MobileFaceNet model.

    face_embeddings

  Field          Type        Description
  -------------- ----------- --------------------------
  id             int         Primary key
  employee_id    int         Foreign key to employees
  embedding      json/blob   128-dimensional vector
  updated_time   datetime    Last update time

Example embedding:

    [0.12, -0.34, 0.56, ...]

------------------------------------------------------------------------

## 3.4 Attendance Table

Stores attendance records.

    attendance

  Field         Type       Description
  ------------- ---------- --------------------
  id            int        Primary key
  employee_id   int        Employee reference
  time          datetime   Attendance time
  type          string     checkin / checkout
  image_url     string     Snapshot of face
  latitude      double     GPS latitude
  longitude     double     GPS longitude
  device_id     string     Device identifier
  created_at    datetime   Record creation

------------------------------------------------------------------------

# 4. API Design

## 4.1 Authentication APIs

### Login

    POST /api/auth/login

Request:

    {
      "username": "teacher01",
      "password": "123456"
    }

Response:

    {
      "token": "jwt-token",
      "userId": 10,
      "role": "teacher"
    }

# 5. Employee Management APIs

### Get employee list

    GET /api/employees

### Get employee detail

    GET /api/employees/{id}

### Create employee

    POST /api/employees

### Update employee

    PUT /api/employees/{id}

# 6. Face Data APIs

### Upload face embedding

    POST /api/faces

Request:

    {

    GET /api/faces

    [
     {

# 7. Attendance APIs

### Submit attendance

    POST /api/attendance

Example request:

    {
     "employeeId": 10,
     "time": "2026-03-10T08:01:22",
     "type": "checkin",
     "latitude": 16.047,
     "longitude": 108.206
    }

### Get attendance records

    GET /api/attendance

### Get attendance by employee

    GET /api/attendance/{employeeId}

# 8. Data Synchronization Flow

## Face Data Sync

    Server → Mobile App

Steps:

1.  App requests `/faces`
2.  Server returns list of embeddings
3.  App stores embeddings locally
4.  Face recognition runs offline

------------------------------------------------------------------------

## Attendance Sync

    Mobile App → Server

Steps:

1.  User performs face check-in
2.  Record saved locally on device
3.  App sends data to `/attendance`
4.  Server stores record in database
